The agent that cites its work.

The Stablecoin Compliance Agent analyses reserve backing — comparing a stablecoin's latest attestation against live on-chain supply — and explains what is notable from a regulatory examiner's view. Three layers, nothing free-floating: facts from deterministic tools, judgement framed by a human-curated corpus, every claim traceable.

00 · Principle

Why the system is shaped this way

A compliance tool may never guess.

An AI compliance product that is confidently wrong is worse than no product. It tells an issuer they are fine when they are not, and the first time a regulator or a CCO catches it, trust is gone.

So the system is built around one rule: the agent reasons, but it never establishes facts. Numbers — on-chain supply, attested reserves, coverage — come only from deterministic tools. Judgements are framed only by a human-curated corpus of authoritative sources. Nothing the agent outputs floats free of a citation.

That gives three layers with hard boundaries. Tools produce facts and cannot be argued with. Corpus supplies the reasoning frame and is gated by a human. Agent synthesises the two and must cite every line.

Each boundary is a typed dataclass, so each layer is independently testable. The whole pipeline runs offline against a fake LLM and mocked RPC — which is how 34 tests guard it against regression in under a tenth of a second.

01 · Layers

The three-layer architecture

Facts. Frame. Judgement.

Tools — the facts

onchain_supply reads ERC-20 supply over JSON-RPC, concurrently, cached. attestation_fetch / extract pull reserve figures from the published PDF. metrics computes coverage, staleness, drift. No interpretation — arithmetic and chain reads.

Deterministic

Corpus — the reasoning frame

A curated set of authoritative sources — regulation, attestation standards, rating-agency methodology. Ingested with section anchors so a citation points to genius-act §4(b), not just a document. Only approved sources are retrievable.

Human-gated

Agent — the judgement

Runs on hermes-agent via the attestation-analysis skill. Synthesises facts + frame into an analysis. Bounded: it may only state figures from the tools, only cite passages from the approved corpus, and must surface every gap.

Bounded LLM
02 · Flow

What analyze() does, in order

One pass, five steps.

1

Resolve on-chain supply

get_onchain_supply — totalSupply across chains, in parallel. Unverified addresses are used but loudly flagged.

2

Fetch + extract the attestation

fetch_latest_attestation then extract_attestation — LLM does structured extraction only, with a confidence score.

3

Compute metrics

compute_metrics — coverage ratio, attestation staleness, supply drift. Pure arithmetic, no judgement.

4

Retrieve the reasoning frame

retrieve — BM25 over approved, ingested corpus passages. Empty corpus is reported as a gap, not silently ignored.

5

Synthesise the analysis

synthesize — the SKILL.md rulebook as system prompt; facts + passages as the only permitted inputs. Every claim cited.

03 · Trust

The boundary that makes it safe

Where facts end, judgement begins.

Facts — from tools

  • On-chain supply. A contract call. Not estimated, ever.
  • Attested reserves. Structured extraction from the PDF, with confidence.
  • Coverage, staleness, drift. Arithmetic over the above.
  • Provenance. Each figure carries the tool that produced it.

Judgement — from the agent

  • What is notable. Cited to an approved corpus section.
  • What an examiner asks. Framed against GENIUS / MiCA / FCA.
  • Confidence & gaps. Low extraction confidence is surfaced, not smoothed.
  • No investment view. The agent never says "safe" or "buy".
04 · Curation

Who decides what counts as authoritative

The agent proposes. A human approves.

Deciding which sources are authoritative is domain judgement. If the agent picked its own authorities it would drift toward popular-but-wrong. So curation is gated:

Agent proposes

propose_source()
writes status: proposed

→

Human approves

edits sources.yaml
sets status: approved

→

Agent may cite

retrieve() returns
approved sources only

▲ Code can never write status: approved. The gate is a manual edit, by design.

05 · Evals

The expert-in-the-loop socket

How the agent gets better.

An LLM that reads forums accumulates breadth, not judgement. Judgement improves only against a ground-truth signal. The eval harness is that signal.

A domain operator defines what a good analysis says; each definition becomes a case in cases.yaml with deterministic checks. Break the curation gate, the supply tool, or gap reporting — and evals fail. It is a regression guard and a teaching loop at once.

evals/cases.yaml- id: usdc-supply-resolves symbol: USDC expects: - kind: supply_resolved - kind: gap_contains value: "unverified" # graded by src/sca/evals/harness.py # OPERATOR: add cases as the corpus # is approved and attestations seeded

08 · Audit

An honest look at the five layers

Where it is weak.

The pipeline runs end-to-end on real data. It is also v0.1. Below, each layer with its blind spots, freshness gaps, cross-chain reconciliation gaps, and missing guards — named plainly, because a compliance tool that hides its own limitations is the problem it claims to solve.

1 · Attestation pipeline

Watch
Freshness

Cached URLs never expire by date. A resolved URL is reused while it returns HTTP 200 — so when a new monthly report publishes, the old URL still resolves and last month's figures keep flowing.

Freshness

The locator finds the latest visible report. On JS-heavy sites only old reports sit in static HTML — PYUSD resolved to a Feb-2025 report. Downstream staleness flags it, but it is a real gap.

Guard gap

Extraction is unvalidated. The LLM's numbers are trusted as-is — no check that the reserve breakdown sums to the stated total; negatives and 100× errors pass silently.

Blind spot

Confidence is self-reported. The extracting model scores its own confidence — a confidently-wrong extraction still reports 1.0.

Guard gap

No download content-type check. A 404 HTML page or a scanned image-PDF yields empty or garbage text with no clear error.

2 · On-chain supply

Watch
Recon gap

Configured chains ≠ all chains. USDC and USDT live on 15+ chains; the registry reads a handful. Supply is systematically under-counted — and silently: nothing reports "N of M known deployments seen."

Recon gap

totalSupply ≠ circulating supply. Treasury, locked and bridge-locked tokens inflate the on-chain figure versus the issuer's own circulation basis — a definitional mismatch with the attestation.

Blind spot

Native vs bridged ambiguity. Several chains carry both native and bridged versions of a token; summing both would double-count.

Guard gap

No block / timestamp captured. Each chain is read "latest" with no provenance of when that figure was true.

Blind spot

Single public RPC per chain. A rate-limited or stale RPC that returns a plausible-but-wrong number is not caught — only hard errors are.

3 · Reconciliation

Risk
Recon gap

Coverage divides incomparable things. Point-in-time attested reserves ÷ live supply is apples-to-oranges. The honest backing ratio is reserves ÷ attested tokens; the live ratio is drift-contaminated. Two distinct ratios are collapsed into one.

Blind spot

Coverage says nothing about reserve quality. $100B of T-bills and $100B of affiliated-entity loans both read "102%." Composition risk — the actual compliance question — is extracted but not assessed.

Recon gap

Cross-chain is a bare sum. No mint/burn parity, no bridge-collateralisation check, no per-chain anomaly detection.

Guard gap

No tolerance bands or sanity bounds. Metrics are raw numbers; nothing classifies "breach" vs "note," and a 50× coverage from a 100× extraction error passes unchallenged.

Blind spot

Snapshot only. No time series — a slow coverage decline or an accelerating drift is invisible.

4 · Interface & citations

Watch
Blind spot

No machine-readable output. The CLI prints prose — no --json. An agent product needs composability.

Blind spot

Citations are inline strings, not resolvable links. You cannot click a citation and open the source passage it points to.

Guard gap

Coverage colour thresholds are hardcoded in the theme. A policy decision (green/amber/red) lives in the presentation layer.

Freshness

No persistence. Every run is ephemeral — no "coverage was 105% last month" diff, no push alerting; pull-only and terminal-only.

5 · Agent reasoning

Risk
Blind spot

Citation discipline is instructed, not verified. SKILL.md tells the model to cite every claim — nothing checks the narrative's figures against the facts packet. The trust mechanism is unenforced.

Guard gap

No number-hallucination guard. A digit typo in the narrative is not diffed against the tool outputs.

Blind spot

"Gap detection" is mostly hardcoded if statements. The agent cannot surface a gap it was not programmed to look for; LLM-noticed issues are not captured as structured gaps.

Guard gap

Gaps are flat strings. No severity, no category — a regulator-facing tool needs "breach" distinct from "note."

Blind spot

No prompt-injection defence. Untrusted PDF and corpus text is fed to the model with no framing as data — a malicious document could carry instructions.

Guard gap

Evals test plumbing, not reasoning. All cases are structural; a regression in analytical quality would not be caught.

Impact HighEffort Low

Impact HighEffort Low

Impact MedEffort Low

Citation verification. Post-process the narrative — every figure must trace to the facts packet or it is flagged. Makes the trust mechanism real instead of instructed.

Impact HighEffort Med

Impact HighEffort Med

Prompt-injection hardening. Delimit all untrusted document and corpus text; instruct the model to treat it strictly as data.

Impact HighEffort Med
